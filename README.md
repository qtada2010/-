## 📌 ما هذا المشروع؟

بوت ديسكورد يُدار بالكامل من **لوحة تحكم ويب** بدل تعديل الكود. كل أمر يعمل بصيغتين
(`/الأمر` و `!الأمر`)، وكل الصلاحيات والاختصارات والتفعيل/الإيقاف تُضبط من المتصفح.

| النظام | ماذا يفعل |
|---|---|
| 🎫 **التذاكر** | لوحات تذاكر بأزرار وقوائم منسدلة، استلام، نسخ محادثة (transcript) |
| 🏰 **الكلانات** | إنشاء كلانات، لوحات تقديم، إدارة أعضاء |
| 📈 **الإكسبي** | مستويات، توب يومي/أسبوعي/شهري، أرشفة وتصفير تلقائي |
| 🛡️ **الإشراف** | حظر، طرد، كتم، تحذيرات، نقاط، قفل/إخفاء رومات |
| 💰 **الخدمات** | حاسبة ضريبة، استدعاء، ألوان، سمعة، أرصدة |
| 🖥️ **لوحة التحكم** | ضبط كل ما سبق من المتصفح بدون لمس الكود |

## 🚀 التشغيل في ٤ خطوات

```bash
# 1) ثبّت الاعتماديات
npm install

# 2) أنشئ ملف الإعدادات من النموذج
cp .env.example .env

# 3) املأ القيم المطلوبة داخل .env  (التفاصيل في الجدول أدناه)

# 4) شغّل البوت
npm start
```

بعد التشغيل تفتح لوحة التحكم على `http://localhost:3000`.

### متغيرات البيئة

| المتغيّر | إلزامي | الوصف |
|---|:---:|---|
| `DISCORD_TOKEN` | ✅ | توكن البوت من [Discord Developer Portal](https://discord.com/developers/applications) |
| `DATABASE_URL` | ✅ | رابط PostgreSQL — `postgresql://user:pass@host:5432/db`. مع Supabase استخدم **Transaction pooler** على المنفذ `6543` لتجنّب خطأ `EMAXCONNSESSION` |
| `PG_POOL_MAX` | ❌ | حد اتصالات قاعدة البيانات لكل نسخة (افتراضي `5`). قلّله إذا شغّلت أكثر من نسخة |
| `DASHBOARD_PASSWORD` | ✅ | كلمة مرور اللوحة. **إن تُركت فارغة يتعطّل الدخول بالكامل** (حماية مقصودة) |
| `PORT` | ❌ | منفذ اللوحة (افتراضي `3000`) |
| `DASHBOARD_URL` | ❌ | الرابط العام للوحة، يُستخدم في أزرار البوت |

> 💡 الجداول تُنشأ تلقائياً في قاعدة البيانات عند أول تشغيل — لا تحتاج تشغيل أي migration يدوياً.

## 🧪 التحقق قبل أي تعديل

المشروع فيه شبكة أمان تثبت أن تعديلك لم يكسر شيئاً:

```bash
npm run verify          # فحص النحو + كل الاختبارات  ← شغّله دائماً
npm test                # الاختبارات وحدها
npm run check           # فحص النحو وحده
```

### إثبات أن صفحات اللوحة لم تتغيّر

قبل التعديل وبعده، التقط لقطة من كل صفحة وقارنهما:

```bash
npm run snapshot:before   # قبل التعديل
#  ... نفّذ تعديلك ...
npm run snapshot:after    # بعد التعديل
npm run snapshot:diff     # يخبرك بالضبط ما الذي تغيّر
```

المقارنة تتحقق من أن كل بطاقة أمر ما زالت موجودة، وأن محتواها لم يتغيّر، وأن
كل مسار حفظ (`form action`) باقٍ — فلا يمكن أن يختفي أمر دون أن تلاحظ.

> 🔒 اللقطات تستخدم قاعدة بيانات وهمية وعميل ديسكورد وهمي — لا تلمس بياناتك
> الحقيقية ولا تتصل بالإنترنت.

## 🔤 قاعدة الترتيب الأبجدي

كل قائمة أوامر في المشروع مرتّبة أبجدياً (a → z)، عبر مصدر واحد هو
`commandSorting.js`. هذا يشمل:

- صفحة `/commands` في اللوحة (بطاقات الأوامر والصلاحيات)
- صفحة `/commands-list` العامة
- قائمة `$help` و `/help` داخل ديسكورد
- ملف `commandCategories.js` نفسه
- ملف `COMMANDS.md`

المقارن يفهم العربية والإنجليزية: يتجاهل الإيموجي في بداية العنوان، ويوحّد
صيغ الألف والهمزة (`الإدارة` = `الادارة`)، ويرتّب الأرقام رقمياً
(`status2` قبل `status10`).

**عند إضافة أمر جديد: ضعه في موضعه الأبجدي.** هناك اختبار يفشل إن لم تفعل.

## 🛡️ ملاحظات أمنية

- كلمة مرور اللوحة **لا تُخزَّن في الكوكي** — يُخزَّن توكن مشتق منها عبر HMAC-SHA256
- كل مقارنات كلمة المرور ثابتة الزمن (`timingSafeEqual`)
- حدّ ١٠ محاولات دخول فاشلة كل ١٥ دقيقة لكل عنوان IP
- الكوكي `HttpOnly` + `SameSite=Lax` + `Secure` تلقائياً على HTTPS
- كل استمارات POST محمية بتوكن CSRF
- كل استعلامات SQL مُمرَّرة بمعاملات (`$1, $2`) — لا تسلسل نصوص
- كل مخرجات HTML تمرّ على `escapeHtml`

> ⚠️ **لا ترفع ملف `.env` إلى GitHub أبداً.** هو مستثنى في `.gitignore`.
